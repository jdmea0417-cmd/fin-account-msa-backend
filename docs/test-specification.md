# 테스트 명세서

## TS-001 인증 및 권한 관리 시나리오 (Security & Gateway)

모든 시스템 접근 요청에 대해 보안 정책(인증/인가)이 적절하게 적용되는지 검증한다.

### TC-001-001: JWT 유효성 검사 실패 테스트

만료되었거나 서명이 잘못된 Access Token 또는 토큰 누락 상태로 핵심 API(계좌 조회, 거래 요청, 알림 조회)에 접근을 시도한다.

- [x] API Gateway 단계에서 401 Unauthorized 응답 코드를 반환하는가
- [x] 토큰이 없거나 형식이 잘못된 요청을 비즈니스 로직 도달 전에 차단하는가

> Spring Cloud Gateway의 `AuthorizationHeaderFilter`를 통해 `/auth/login/**` 및 계좌 생성(`POST /accounts`), H2 콘솔을 제외한 모든 보호된 경로(`/accounts/**`, `/transactions/**`, `/notifications/**`)에 대해 JWT 서명 및 만료 검증을 수행하며, 유효하지 않은 경우 401 Unauthorized를 반환합니다.

### TC-001-002: 역할 기반 접근 통제 (RBAC) 테스트

일반 사용자 계정으로 관리자만 사용할 수 있는 API에 접근을 시도한다.

- [ ] 403 Forbidden 응답 코드를 반환하는가
- [ ] 해당 요청이 비즈니스 로직에 도달하기 전에 차단되는가

### TC-001-003: Gateway 라우팅 검증

외부에서 들어오는 트래픽이 오직 API Gateway 를 통해서만 접근 가능하며, 게이트웨이가 적절한 서비스로 요청을 분기(Route) 하는지 확인한다.

- [x] 잘못된 경로 요청 시 404 Not Found 가 반환되는가
- [x] 내부 마이크로서비스가 외부 노출되지 않는가

## TS-002 계좌 생명주기 관리 시나리오 (Account Lifecycle)

계좌 생성부터 폐쇄까지의 모든 상태 전이 로직과 비즈니스 규칙을 검증한다.

### TC-002-001: 정상적인 계좌 개설 흐름 테스트

필수 정보(성명, 비밀번호 등)를 입력하여 신규 계좌를 생성하고, 최초 조회 시 잔액 0과 ACTIVE 상태가 부여되는지 확인한다.

- [x] 성공 응답 코드 (201 Created)를 반환하는가
- [x] 데이터베이스에 정상적으로 레코드가 저장되었는가

### TC-002-002: 계좌 중복 생성 방지 테스트

동일한 계좌번호 또는 잘못된 데이터로 계좌를 생성하려 할 때, 시스템이 이를 감지하고 트랜잭션을 실패시키는지 검증한다.

- [x] 비즈니스 로직 레벨에서 오류가 발생하는가 
- [x] 유효성 검증 실패 시 적절한 에러 코드를 반환하는가

### TC-002-003: 상태 전이 무결성 검증 (State Machine)

비활성화(INACTIVE) 상태의 계좌에 입금 또는 이체 시도를 하거나, 이미 폐쇄(CLOSED)/동결(FROZEN)된 계좌에서 거래를 시도할 때 시스템이 이를 차단하는지 확인한다.

- [x] 해당 상태에서의 모든 트랜잭션 요청은 400 Bad Request 에러를 반환하는가

## TS-003 분산 트랜잭션 처리 시나리오 (Transaction & Consistency)

자금 이동 과정에서 발생하는 데이터 불일치 및 실패 상황을 안정적으로 복구하는지 검증한다.

### TC-003-001: 정상적인 입출금 흐름 테스트

잔액이 충분한 계좌에서 출금/입금을 진행하여 트랜잭션을 완료시키고, Account Service 와 Transaction Service 의 잔액 및 거래 내역이 모두 정확히 일치하는지 확인한다.

- [x] 분산 트랜잭션 처리가 원자적으로(Atomically) 성공하는가
- [x] 모든 관련 서비스의 DB에 기록이 남는가

### TC-003-002: 자금 부족 및 롤백 테스트 (Fallback)

출금 대상 계좌의 잔액보다 큰 금액을 출금 요청했을 때, 잔액 차감 없이 거래가 실패(FAILED) 처리되는지 검증한다.

- [x] 잔액 부족 시 400 Bad Request 및 FAILED 거래 이력이 기록되는가
- [x] 원장 잔액이 차감되지 않고 온전하게 보존되는가

### TC-003-003: 비동기 이체 및 보상 트랜잭션 검증 (Saga)

계좌 A 에서 계좌 B 로 이체를 시도할 때, 계좌 A 에서 잔액을 차감한 뒤 계좌 B 에 입금하는 도중 오류(B 계좌 비활성, 네트워크 장애 등)가 발생한 경우 Saga 보상 트랜잭션(Compensating Transaction)이 작동하는지 확인한다.

- [x] 시스템이 자동적으로 A의 출금액을 다시 A 계좌로 환불(보상 입금)하는가
- [x] 트랜잭션 상태가 FAILED로 안전하게 종료되고 알림이 발송되는가

## TS-004 성능 및 안정성 시나리오 (Non-Functional Testing)

극한 상황(대규모 요청, 장애)에서도 서비스 연속성과 예측된 성능을 유지하는지 검증한다.

### TC-004-001: 동시성 부하 테스트 (Race Condition)

1초 동안 다수의 가상 사용자가 계좌에 동시에 거래 요청을 보내는 부하 상황을 시뮬레이션한다.

### TC-004-002: 장애 주입 및 복구 테스트 (Chaos Engineering)

시스템 운영 중, 핵심 서비스 컨테이너를 중단시키거나 지연을 유발할 때 Circuit Breaker가 작동하는지 검증한다.

- [x] Circuit Breaker가 작동하는가
- [x] Resilience4j를 통해 Account Service 장애 시 Transaction Service가 안전하게 차단/복구되는가
- [x] Kafka 알림 발행 실패 시에도 핵심 거래 로직이 격리되는가
